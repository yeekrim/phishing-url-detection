# v3 — 최신 데이터셋·논문으로 다시 만든 피싱 페이지 탐지기

v2에서 2012년 논문(Mohammad·Thabtah·McCluskey)의 피처가 지금 데이터에서는 거의 쓸모없다는 것을 확인했습니다(피처 하나씩의 AUC 0.50~0.53, `reports/v2/shortcut_checks.md`).
v3에서는 2024~2025년 논문과 공개 데이터셋으로 탐지기를 처음부터 다시 만들었습니다. LLM은 쓰지 않고, **피처와 머신러닝만** 사용합니다.

## 결과 요약

PhreshPhish 벤치마크에서 잰 평균 AP입니다(높을수록 좋음). 벤치마크는 피싱 비율이 0.05%~5%인 평가 세트 975개로 이루어져 있고, 실제 환경처럼 피싱이 드문 상황을 흉내 냅니다.

| 모델 | 0.05% | 0.1% | 0.5% | 1% | 5% |
|---|---|---|---|---|---|
| **v3 최종 (피처 + n-gram 점수, LightGBM)** | **0.626** | **0.703** | **0.845** | **0.891** | **0.959** |
| [논문] GTE (BERT 계열) | 0.605 | 0.688 | 0.835 | 0.876 | 0.938 |
| [논문] Linear (n-gram + 피처) | 0.223 | 0.319 | 0.583 | 0.684 | 0.861 |

- 평가(test) 데이터 전체(168,060행)에서 ROC-AUC 0.996, 오탐률 1%일 때 탐지율 94.6%, 오탐률 0.1%일 때 탐지율 76.2%입니다.
- 모든 피싱 비율에서 논문의 GTE보다 높습니다. 다만 피싱 비율 0.1% 이하에서는 차이가 0.01~0.02로 작습니다.
- 논문 수치는 논문 표 4를 그대로 옮긴 것입니다. 아래 "데이터셋의 지름길"에서 고친 문제가 논문 모델에도 영향을 줬는지는 확인하지 못했습니다(논문 모델을 다시 돌리지 않음).

## 데이터

**PhreshPhish** (Dalton 외, 2025, arXiv 2507.10854, CC BY 4.0, 피싱 대응 연구 용도로만 사용)

- URL과 HTML 원본을 함께 제공합니다. train 498,255행(피싱 221,526), test 168,060행(피싱 76,800)입니다.
- test가 train보다 나중 시점입니다(시간 분할). 그대로 사용했습니다.
- 원본은 HTML을 포함해 36.6GB입니다. 디스크에 다 둘 수 없어서 파일 단위로 **받기 → 피처·벡터 추출 → 원본 삭제**를 반복했습니다. 원본과 URL 목록은 저장소에 올리지 않습니다.
- test의 피싱 수가 README의 76,876건과 76건 차이 납니다. 원인은 확인하지 못했습니다.

## 데이터셋의 지름길 — 찾아서 없앤 것

모델이 피싱의 특징이 아니라 **데이터를 모은 방식의 차이**로 맞히는 경우를 4개 찾았습니다. 모두 두 클래스에 같은 정규화를 적용해 없앴습니다.

| 지름길 | 근거 (train/test 실제 비율) | 처리 |
|---|---|---|
| 쿼리 문자열(`?...`) | 정상 0% / 피싱 6.8%. 논문 부록 A.2: 개인정보 제거를 "정상 클래스에만" 함 | 두 클래스 모두 쿼리·프래그먼트 삭제 |
| URL 대소문자 | 대문자가 있는 URL: 정상 13%(train·test 같음) / 피싱 train 17%, test 2% | 소문자로 통일 |
| URL 끝의 `/` | 경로 없는 URL: 정상 0% / 피싱 train 6%, test 42% | 끝의 `/` 삭제 |
| HTML 맨 앞 DOCTYPE | DOCTYPE으로 시작: 정상 1% 미만 / 피싱 train 0%, test 75% | DOCTYPE 삭제 |

뒤의 두 개를 고치자 벤치마크 AP(0.05%)가 0.646에서 0.568로 떨어졌습니다. 이전 점수의 일부는 지름길 덕분이었다는 뜻입니다. 그 뒤의 개선(아래)은 모두 정규화한 데이터 위에서 잰 것입니다.

## 피처와 근거 논문

| 종류 | 내용 | 근거 |
|---|---|---|
| URL 어휘 | 길이, 특수문자, 하위 도메인 수, IP·포트·퓨니코드, 엔트로피, 의심 단어, 사이트 이름의 모양 | PhreshPhish 기준 모델과 기존 연구에서 널리 쓰는 피처 |
| HTML 구조 | 내부·외부·빈 링크, 외부 CSS·JS, 난독화 스크립트, 폼·비밀번호 입력란, iframe, 메타 태그 등 | Çolhak 외, arXiv 2401.04820 (C3~C13; 논문에 정의가 없는 것은 이름에 맞게 직접 정의) |
| 브랜드-도메인 일치 (BDI) | 로고·폼 전송·가장 흔한 링크의 도메인이 페이지 도메인과 같으면 1, 다르면 -1, 없으면 0 | Mishra & Varshney, arXiv 2503.06487 (HTML만으로 계산 가능한 3개만 사용) |
| n-gram | URL 글자 3~5-gram, HTML 앞 5,000자 단어 1~2-gram, 제목+본문 전체(최대 20만 자) 단어 1~2-gram | PhreshPhish의 Linear 기준 모델 |
| 설명 | LightGBM SHAP, n-gram 가중치를 원래 조각으로 되돌려 보기 | Mia 외, arXiv 2411.09813 (SHAP으로 피처를 믿을 만한지 확인) |

도메인 비교는 공개 접미사 목록의 사설 항목(github.io, netlify.app 등)까지 반영한 등록 도메인으로 합니다. `a.github.io`와 `b.github.io`는 운영자가 다르기 때문입니다.

## 모델

1. **n-gram 선형 모델 2개**(SGD, 로지스틱 손실): URL만 쓰는 모델, URL+HTML+본문을 쓰는 모델.
   - train 안에서 등록 도메인 묶음으로 5-겹 교차 예측 점수를 만듭니다. 같은 사이트가 학습과 검증 양쪽에 들어가지 않습니다.
2. **LightGBM**: 손으로 만든 피처 67개와 위 두 점수를 함께 사용합니다(스태킹).

**설정 고르기** — 평가(test) 데이터는 쓰지 않았습니다(`reports/v3/tuning.md`).

- 기준 점수는 피싱 비율 0.05/0.1/0.5/1/5%에서의 AP 평균입니다. 검증 데이터의 피싱 행에 가중치를 줘서 벤치마크와 같은 비율을 흉내 냅니다.
- n-gram 모델의 규제 강도는 교차 예측 점수로 골랐습니다.
- LightGBM은 train에서 가장 최근 15%를 검증용으로 떼어 골랐습니다(test가 train보다 나중이므로 같은 방향). 검증과 도메인이 겹치는 행은 학습에서 뺐습니다. 조기 종료도 같은 기준 점수로 합니다.

## 개선 과정

| 단계 | 0.05% | 0.1% | 오탐률 0.1%일 때 탐지율 |
|---|---|---|---|
| 지름길 4개 제거 후 | 0.568 | 0.652 | 72.2% |
| + 호스팅 플랫폼 정상 가중치, 사이트 이름 피처, 설정 고르기 | 0.626 | 0.699 | 73.8% |
| + 본문 전체 n-gram | 0.626 | 0.703 | 76.2% |

- **호스팅 플랫폼 정상 가중치**: train에서 호스팅 플랫폼 페이지는 정상 697개, 피싱 68,007개입니다. 그래서 모델이 "플랫폼이면 피싱"으로 배우기 쉬웠고, 실제로 오탐의 16.5%가 플랫폼 정상 페이지였습니다(정상 전체 중에서는 0.2%). 효과는 작았습니다(오탐률 0.1% 기준 플랫폼 오탐 15 → 13건).
- **설정 고르기**: 개선 대부분이 여기서 나왔습니다. n-gram 규제를 약하게 바꾸고(alpha 3e-6 → 1e-6), LightGBM 설정과 반복 횟수를 바꿨습니다.
- **본문 전체**: train 안의 두 검증 점수와 test가 모두 같은 방향으로 조금씩 올랐습니다(교차 예측 0.8393 → 0.8455).

## SHAP으로 본 판단 근거

`reports/v3/explain.md`

- 최종 모델 판단의 약 63%가 n-gram 점수에서 나옵니다(URL+HTML+본문 53%, URL 10%).
- 손으로 만든 피처 중에서는 내부 링크 수, HTML 길이, 호스트 길이, 경로 길이가 큽니다. 피싱 페이지는 링크가 적고 HTML이 짧습니다.
- 피싱 쪽 n-gram: `webmail`, `whatsapp`, `wallet`, `verify`, `banking`, `dhl`, `.top`, `.shop`, `http:` 등 실제 피싱 수법과 맞는 조각입니다.
- 정상 쪽 n-gram: `search`, `health`, `calendar`, `events` 등 일반 사이트의 조각입니다.

## 한계

- **피싱 비율 0.1% 이하에서는 GTE와의 차이가 작습니다.** 실제 환경과 가장 가까운 구간이라, 더 낫다고 단정하기는 어렵습니다.
- **학습 때 없던 공격 대상**: test 피싱의 51.6%는 train에 한 번도 나오지 않은 브랜드를 노립니다. 특히 다음 두 묶음은 피처만으로 구분할 근거가 거의 없어 보입니다.
  - `google` 대상 9,132건: 대부분 평범해 보이는 blogspot 블로그입니다. train에는 25건뿐이고, 탐지율은 52%입니다.
  - `grandlisboamacau` 대상 3,832건: 빈 페이지이거나 보안 인증 화면입니다. 탐지율은 27%입니다.
- **데이터 구성 때문일 수 있는 신호가 남아 있습니다.** 피싱은 도메인 첫 페이지 비율이 47~62%이고 정상은 7~9%입니다. 또 `.jp`가 정상 쪽으로 강하게 기웁니다. 첫 페이지만 따로 보면 AUC 0.991, 깊은 경로 페이지만 보면 0.993으로 비슷하지만, 실제 환경에서도 이 차이가 성립할지는 확인하지 못했습니다.
- **손으로 만든 피처만 쓴 LightGBM은 오히려 나빠졌습니다**(0.05% 기준 0.392 → 0.339). 최근 데이터로 검증해 고른 설정이 test와 맞지 않았습니다. 최종 모델에는 들어가지 않는 비교용 모델입니다.
- **다른 데이터셋에서는 검증하지 않았습니다.** v2 데이터는 HTML이 없어 그대로 쓸 수 없습니다.

## 실행 방법

```bash
pip install -r requirements-v3.txt
cd <저장소 루트>
export PYTHONPATH=src/v3

python src/v3/extract_phreshphish.py      # 받기 → 피처 추출 → 원본 삭제 (파일 77개, 수 시간)
python src/v3/text_vectors.py             # n-gram 벡터 (URL, HTML 앞부분, 본문 앞부분)
python src/v3/extract_fulltext.py         # 본문 전체 벡터 (원본을 다시 받아 벡터만 만들고 삭제)
V3_VECTORS=data/v3/interim/vectors_full python src/v3/train.py   # 설정 고르기 + 학습
python src/v3/evaluate.py                 # test 전체 + 벤치마크 → reports/v3/evaluation.md
V3_VECTORS=data/v3/interim/vectors_full python src/v3/explain.py # SHAP·n-gram → reports/v3/explain.md
python -m pytest tests/v3                 # 피처 계산 단위 테스트
```

Mac(메모리 8GB) 기준으로 학습은 약 25분 걸립니다. 추출은 네트워크 속도에 따라 수 시간 걸립니다.
